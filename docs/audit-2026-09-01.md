# MX 文件管理器 全面审计报告（多 Agent 编排）

- 审计日期：2026-09-01
- 审计方式：5 个只读 subagent 并行（文件所有权隔离），主 agent 汇总
- 对标目标：**完全覆盖 Windows 资源管理器 + macOS 访达，并做得更好；极致性能**

| Agent | 范围 | 结论 |
|---|---|---|
| audit-fs-core | src/fs/ + stores + utils | 基础操作完成度高；**大文件 IO 架构性硬伤 P0×3**，系统级集成（剪贴板/回收站/驱动器）缺失 |
| audit-electron | electron/ + CI + 打包 | 壳层是"能用的最小实现"；**mxfile:// + IPC 无路径校验是最大攻击面** |
| audit-viewers | src/viewers/ | 覆盖矩阵广（15 类）；**桌面端解码链路断裂 P0**，中文场景两大乱码源 |
| audit-ui | src/components/ + App | 基础交互高于平均线；**外部拖入断链 P0**、假快捷键、键盘可达性缺失 |
| audit-perf | 全项目性能维度 | 虚拟滚动 7/10 良好；**首包 1MB+ 冗余、整店订阅全树重渲染、懒 stat 缺失** |

## 一、P0 缺陷汇总（跨领域，按修复紧迫度）

| # | 领域 | 问题 | 位置 | 影响 |
|---|---|---|---|---|
| 1 | 文件操作 | **所有复制/移动把整个文件读进渲染进程内存**：getFile 全读 → blob.arrayBuffer() → 整包 IPC | `src/fs/ops.ts:55-57`、`src/fs/electron.ts:143-151`、`electron/main.cjs:226-228` | 复制 2GB 视频 ≈ 4GB+ 内存，OOM/崩溃 |
| 2 | 安全 | **mxfile:// 协议无路径白名单**，任意路径转 file:// 读盘；fs:* IPC 同样收任意路径；无 CSP + sandbox:false。三者叠加 = XSS → 全盘任意读写删（预览器渲染大量不可信内容，注入面真实存在） | `electron/main.cjs:367-377, 206-268`、`index.html` | 安全根基缺陷，预览功能越多暴露面越大 |
| 3 | 数据丢失 | **回收站删除失败静默转永久删除**：trashItem 失败直接 rm，返回值不回传 UI；确认框写的是"移入回收站" | `electron/main.cjs:238-246` | 网络盘/U 盘删除 = 无提示数据丢失 |
| 4 | 查看器 | **桌面端 TIFF/HEIC/PSD 必然打不开**：useBlobUrl 优先取 mxfile:// URL，imageDecode.ts 的 needsImageDecode() 写了但没被调用，解码器被完全绕过 | `src/viewers/registry.tsx:249-255` + `src/utils/imageDecode.ts:6` | 核心卖点"点击即开"在桌面版主格式上失效 |
| 5 | 交互 | **外部文件/文件夹拖入完全不可用**：onDragOver 仅在内部 payload 存在时 preventDefault，外部 drop 永远不触发 importExternal；Welcome 页承诺"拖进窗口"失效；且无 window 级拦截，浏览器版拖到列表外会直接打开文件 | `src/components/FileList.tsx:191-197, 212-245` | 获客级交互失效 |
| 6 | 操作安全 | **无任何取消机制**：copyEntries/deletePaths 无 AbortSignal，误拖巨大目录只能强杀；移动 = 递归复制+删除，中途失败留双份脏状态 | `src/fs/ops.ts:17-91`、`src/stores/fs.ts:244-249` | 数据一致性风险 |
| 7 | 性能 | **超大图解码 100% 主线程无降采样**：TIFF/PSD 全量 arrayBuffer + 同步 RGBA（100MP ≈ 400MB 峰值 >1GB），无 Worker | `src/utils/imageDecode.ts:28-53` | 开大图冻结数十秒、OOM |
| 8 | 查看器 | **GBK CSV 乱码**：CsvViewer 用 f.text() 未走已有的 decodeSmart | `src/viewers/CsvViewer.tsx:131` | 中文 Excel 导出 CSV 高频场景直接坏 |
| 9 | 压缩包 | **加密压缩包零支持**且无密码 UI；**GBK zip 中文文件名全乱码**；zip 解压在主线程（unzipSync） | `src/viewers/ZipViewer.tsx:56-79` | 高频硬缺口 |
| 10 | 性能 | **整店 Zustand 无 selector 订阅**：op 进度每文件一次 set → 全树重渲染，行无 memo | `App.tsx:22`、`FileList.tsx:68` 等 | 大目录操作时 UI 卡顿放大器 |
| 11 | 性能 | **xlsx/CodeMirror/查看器全部打进首包**：memory.ts 静态 import XLSX 拖入主 chunk；registry.tsx 静态注册 12 个查看器；全项目 0 个 React.lazy | `src/fs/memory.ts:5-6`、`src/viewers/registry.tsx:9-20` | 首包 +1MB+，TTI 恶化 |
| 12 | 性能 | **只读文本无大小上限**：TEXT_LIMIT 只挡编辑，只读模式 2GB 日志全量读入 → OOM | `src/viewers/TextViewer.tsx:154` | 崩溃路径 |
| 13 | 目录移动 | **目录移动永远走"递归复制+删除"而非原生 rename**（单文件才有原生路径） | `src/stores/fs.ts:244-249` | 慢 + 中断出脏状态 |

## 二、功能差距矩阵 vs 资源管理器/访达

### 2.1 文件操作层（16 项对照）

| 能力 | 判定 | 差距说明 |
|---|---|---|
| 基础操作（新建/重命名/复制/粘贴/删除） | ✅ | 齐全 |
| 撤销/重做 | ⚠️ | 覆盖 4 种操作；**删除不可撤销**、栈内存态重启失效、撤销用 overwrite 静默覆盖新文件 |
| 冲突处理 | ⚠️ | 整批一次性选择，无逐项预览（大小/mtime 对比）；无只读/系统文件保护 |
| 多选 | ⚠️ | 无橡皮筋框选、无反选、无选择记忆 |
| 排序 | ⚠️ | 自然排序+目录优先有；次级排序非自然、目录 size 恒 0、无分组排序 |
| 搜索 | ⚠️ | 仅当前目录子串；**无递归搜索、无通配符、无内容搜索** |
| 系统剪贴板 | ❌ | 纯应用内状态，与 Explorer/Finder 双向不通 |
| 压缩 | ⚠️ | 只能解压不能压缩；解压无进度/取消 |
| 驱动器管理 | ⚠️ | 无 U 盘热插拔监听、无弹出、无磁盘容量；mac 不枚举 /Volumes |
| 回收站浏览与还原 | ❌ | 完全缺失 |
| 文件属性 | ❌ | 无权限/所有者；不识别 Windows hidden 属性；无目录递归大小 |
| Windows 文件名规则 | ❌ | 非法字符/保留名不拦截；260 长路径无 \\?\；**仅改大小写被拒** |
| 大文件复制（进度/取消/预检） | ❌ | 全量内存中转，见 P0-1 |
| 符号链接 | ❌ | 无 lstat，broken link 显示 size 0 |
| 文件关联打开 | ✅ | shell.openPath 完整 |
| 标签/固定 | ⚠️ | 有最近文件；无 Finder 标签、无快速访问 |

## 三、性能评分与优化路线

**六维评分**：启动 4/10 · 目录列举 4/10 · 虚拟滚动 7/10 · 缩略图 4/10 · 内存 6/10 · 文件 IO 6/10

**Top 10 优化（收益/成本排序）**：

| # | 优化项 | 预估收益 | 成本 |
|---|---|---|---|
| 1 | **懒 stat 列举**：list 只返回 name+kind，size/mtime 对可见窗口批量 statMany | 10 万文件目录首屏 3-8s → 300-600ms | 中 |
| 2 | **首包瘦身**：memory.ts 改动态 import；查看器全 React.lazy；CodeMirror 随 TextViewer 懒加载 | 首包 -1MB+，TTI -40% | 低 |
| 3 | **selector 化 + 行 memo**：细粒度订阅 + React.memo(Row) | 操作/滚动重渲染范围全树→单行 | 中 |
| 4 | **缩略图降采样 + 并发闸**：createImageBitmap(resizeWidth:224) + 信号量(4-6) + in-flight 去重 | 大图目录内存数百MB → <80MB | 低-中 |
| 5 | **vite manualChunks** 分组 | 缓存粒度改善 | 极低 |
| 6 | **只读大文本保护**（TEXT_LIMIT 对 readOnly 生效或分片读取） | 消除 OOM 崩溃路径 | 低 |
| 7 | **Intl.Collator 缓存**（模块级实例） | 10 万条排序 1-3s → 200-400ms | 极低 |
| 8 | **扫描改造**：localStorage→IndexedDB、空闲触发、queue 索引指针 | 启动 -50-100ms，不再开机打满 IO | 低-中 |
| 9 | **PDF 流式加载**（mxfile:// Range） | 500MB PDF 内存 500MB → ~50MB | 低-中 |
| 10 | **转码 temp TTL 清理 + IPC Transferable** | 磁盘不膨胀、大文件少一次全量拷贝 | 低 |

> Windows MFT 专项：纯 JS 不可行；短期 `opendir` 流式 + 懒 stat 覆盖 90% 收益；长期可选原生 addon（everything SDK 类），百万文件索引分钟级→秒级，但维护成本大。

## 四、修复路线图建议（三阶段）

### Phase 1 —— 止血（P0，先做）
1. 主进程流式复制管道 `createReadStream → pipe` + AbortSignal 取消 + 字节级进度（根治 P0-1/6/13）
2. trash 失败显式报错不降级 + 删除入撤销栈（P0-3）
3. mxfile:// 路径白名单（当前浏览子树 + temp 转码目录）+ fs IPC 校验 + CSP + sandbox:true（P0-2）
4. 桌面端图片解码修复：needsImageDecode 接入（约一处 if，收益/成本比最高）（P0-4）
5. 外部拖入修复：onDragOver 对 Files 类型一律 preventDefault + window 级拦截（P0-5）
6. 快改包：GBK CSV 走 decodeSmart、.xls bookType 修复、假快捷键实现或删除声明、Collator 缓存、首包动态 import

### Phase 2 —— 补齐（对标 Explorer/Finder 核心差距）
1. 回收站浏览与还原（Win $Recycle.Bin / macOS ~/.Trash）
2. 系统剪贴板双向集成（clipboard FileNameW format）
3. 多窗口支持 + 单实例锁 + 自动更新（electron-updater）
4. 目录实时监听（chokidar 动态挂当前目录，webContents.send 增量刷新）
5. 递归搜索 + 通配符；属性面板（权限/hidden/目录递归大小）；isValidName 补 Windows 规则
6. pptx 预览 + 视频外挂字幕（srt 自动挂 track）+ 加密压缩包密码 UI
7. 音频全局播放器（切页不停）+ 右键菜单子菜单体系

### Phase 3 —— 极致性能与打磨
1. 懒 stat + opendir 流式列举（或可选 MFT addon）
2. 缩略图 Worker 化 + 降采样闸门
3. 列配置记忆/面包屑下拉/路径补全/橡皮筋框选/键盘 roving tabindex
4. i18n 抽层、主题系统跟随、错误态/骨架屏、签名公证双架构分发

## 五、做得好的（保持）

- Provider 抽象（electron/fsa/capacitor/memory 四实现）架构干净，两版共用 UI
- mxfile:// stream:true 视频零拷贝 seek 思路正确
- 虚拟滚动（react-virtual）、CSV 分片预读、扫描四重熔断（25k 目录/60k 文件/2min/深度）
- blob URL revoke 链路、pdfjs destroy、CM destroy 基本完整（唯一泄漏：ZipViewer 包内预览）
- 转码兜底冷门格式（rmvb/wmv/ape 等 20+ 格式）是同类开源项目少见的亮点
